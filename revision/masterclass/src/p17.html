 Behavioural questions ask for past behaviour as a predictor of future behaviour. Use STAR: Situation (one sentence), Task (your responsibility), Action (what you did, the longest part), Result (outcome + what you learned).
  • Not rehearsed: memorise the story’s facts, not sentences. Start differently each time. Include one specific detail (an error message, a number) that only someone who was there would know.
  • Length: 60–90 seconds, then stop and let them ask.
  • Independent learning: you don’t have team stories, so use solo ones honestly and add “in a team I would…” where relevant.
  • Employment gap: the formula in Phase 1 (fact → choice → evidence → what changed → now).
  • “We did…” when it was you, or “I did…” when it was a team.
  • Stories with no result or no lesson.
  • Blaming tools, teammates, or the market.

17.1Questions

Tell me about a time you couldn’t solve a technical problem.Pick one where you got stuck, changed approach, and either solved it later or worked around it honestly.Strong: “My rate limiter on Render kept putting requests from one user into different counters. I tried trust proxy 1, then 2, and both were wrong. I was guessing, so I stopped and found a way to measure: the RateLimit-Policy header contains a hash of the key, so I compared it with a hash of my real IP. That showed Render has Cloudflare plus its own proxies in front, and 3 was right. Lesson: when I’m guessing twice in a row, I need a measurement.”
Weak: “I never get stuck, I always find it on Stack Overflow.”Persistence, method, honesty. How do you approach debugging?Reproduce, read the actual error and logs, find which component fails by timing or bisecting, form one hypothesis at a time and test it, fix the root cause, then add a test or a log so it can’t come back silently.“My streamed answers sometimes showed nothing. I logged the raw bytes and saw Gemini ends lines with \r\n and a \r\n could be split across two reads, so I normalised line endings on the whole buffer instead of per chunk.”Method (Phase 12). What do you do when documentation is insufficient?Read the library’s source and types, write a tiny experiment script to observe the behaviour, search issues, and write down what I found for the next person.“Before planning workflows I read Mastra’s package source and its bundled docs to confirm the recovery setting and that bail() ends a run as success. For Gemini’s function calling I wrote a probe script with 17 real calls and found the model ignored mode NONE, which changed my design.”Self-sufficiency. How do you decide whether to use AI assistance or solve something independently?I use AI to speed up things I understand and to explain things I don’t yet, but I make sure I can explain and defend every line that ships. For core logic I’m learning, I build it step by step and test it myself first.

Show judgement: boilerplate, docs, test scaffolding → assist freely. Security, data isolation, concurrency → design it yourself, review line by line, test adversarially.

“I never use AI” (unbelievable) or “AI writes most of my code” without the verification part.Modern work habits + ownership. Have you ever used AI-generated code that caused a problem?Yes. How do you verify code generated by AI?Read every line and make sure I can explain it; run the type checker and tests; test edge cases and failure paths deliberately (bad input, network off, another user’s id); check library APIs against the docs for the version I use; review the diff before committing.Ownership. How do you approach code reviews?As the author: small PRs with a clear description and how I tested it. As a reviewer: correctness and security first, then readability, kind and specific comments with reasons, and questions rather than orders.My auth work went through a PR (#3) with a written plan and a per-step results log.Collaboration. How would you respond if a senior developer disagreed with your implementation?Ask them to explain their concern, restate it to be sure I understood, share my reasoning briefly with any data I have, and if it’s still a judgement call, go with their decision and learn from it. What would you do if you were assigned a task involving an unfamiliar technology?Read the official docs’ core concepts, build the smallest working version in a scratch project, then apply it to the task in small steps, and ask early if I’m blocked for more than a set time.“I learned MySQL and Ruby on Rails basics in one session before a walk-in interview; for BullMQ I wrote a learning script that measured an idle worker’s Redis commands before using it in DocMind.”Learning speed. How do you prioritize multiple tasks?By impact and urgency, unblock others first, and check priorities with my lead when unsure. I break work into small deliverable pieces so something useful ships even if plans change.Planning. What do you do when you cannot meet a deadline?Tell the person as soon as I know, with what’s done, what’s left, a new estimate and options (cut scope, get help, move the date).
