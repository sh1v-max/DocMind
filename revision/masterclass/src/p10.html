10.AThe method

System design = turning a vague product request into components, data, APIs and flows, then stress-testing it with failures and growth.
  1. Requirements (3 min): users, core actions, non-functional needs (latency, scale: “1,000 users, 10 uploads/day each?”, privacy, cost). Write assumptions down out loud.
  2. Components (3 min): client, API, auth, database, object storage, queue + workers, LLM/embedding providers, cache, observability.
  3. Data model (3 min): tables and keys; who owns what.
  4. API (2 min): the 4–6 endpoints, request/response, sync vs async (202 + polling/SSE).
  5. Data flow (3 min): walk one request through every box. Interviewers explicitly want the flow, not just boxes.
  6. Failure and scale (rest): what if the LLM is down, a worker crashes, a user uploads 2,000 pages, traffic ×10. Where’s the bottleneck? What’s the first thing you’d add?
  • Starting with Kubernetes and microservices for 1,000 users.
  • Drawing boxes without data flow or ownership.
  • Forgetting authorization, cost and observability.

async function assertPublicUrl(raw) {
  const url = new URL(raw);
  if (!['http:', 'https:'].includes(url.protocol)) throw new HttpError(400, 'Only http(s) URLs');
  const addrs = net.isIP(url.hostname) ? [url.hostname] : (await dns.lookup(url.hostname, { all: true })).map((a) => a.address);
  if (addrs.some(isPrivate)) throw new HttpError(400, 'URL not allowed');
  return url;   // also: fetch with redirect: 'manual' and re-check each hop; cap size and time
}
