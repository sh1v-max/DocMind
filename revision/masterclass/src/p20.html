20.3Questions to ask them at the end

  • What does the first month look like for a new backend engineer here?
  • How do you evaluate quality of the AI features before shipping changes?
  • Which LLM providers and frameworks do you use, and how do you handle outages and cost?
  • How are code reviews done, and how much does the team pair?
  • What’s the biggest technical problem the team is working on right now?

20.4Optional second round

From the bank: “A second round could focus on a longer coding exercise, project architecture and more detailed debugging.” What that usually looks like, and how to prepare:

  • Longer coding (45–60 min): e.g. build a small RAG endpoint with ingestion + retrieval + streaming, or a tool-executing agent with tests. Practise Phase 16 walkthroughs 1 and 2 as real code, timed.
  • Project architecture (30 min): a whiteboard of DocMind with “what if” changes: add teams/workspaces, add a summary feature, scale to 10,000 users, switch embedding model. Phase 13.45–13.50 and Phase 10.
  • Detailed debugging (30 min): a broken repo or logs from an incident. Use the 8-step method out loud (Phase 12), and say what evidence you’d collect before touching code.
