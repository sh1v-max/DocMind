Implement orchestration yourself when the flow is small (one tool loop, one queue), you need exact control (provider quirks like Gemini’s thoughtSignature), or you’re learning. Use a framework when you need durable state, recovery, approvals, tracing and many providers, and don’t want to maintain them.

 DocMind: agent loop hand-written; Mastra planned only for workflows; LangGraph is mentioned in topic 11 as concept material. Three open protocols that standardise different connections in an AI application: MCP (agent ↔ tools/data), A2A (agent ↔ agent), AG-UI (agent ↔ user interface).
  • MCP (Model Context Protocol), started by Anthropic: an MCP server exposes tools (functions the model can call), resources (readable data like files or records, addressed by URI) and prompts (reusable templates). An MCP client inside a host app (an IDE, a chat app, your agent) connects to servers, lists what they offer and calls them. Messages are JSON-RPC 2.0 over stdio (local) or Streamable HTTP (remote). Problem solved: write a connector once, use it from any MCP-capable app, instead of N×M custom integrations.
  • A2A (Agent2Agent), started by Google: agents publish an agent card (JSON describing skills, endpoint, auth); a client agent sends a task with messages; the remote agent works on it (possibly long-running, with status updates and streaming) and returns artifacts. Problem solved: agents from different vendors/frameworks collaborating without sharing internals. MCP = tools for one agent; A2A = peers delegating work.
  • AG-UI (Agent–User Interaction protocol), from CopilotKit: a stream of typed events from agent backend to frontend (run started/finished, text message start/content/end, tool call start/args/end, state snapshots and deltas, errors) over SSE or similar. Problem solved: any frontend can render any agent backend’s progress, tool calls and shared state.

Together: the UI talks AG-UI to your agent; your agent uses MCP servers for tools and data, and A2A to delegate to other agents.

 DocMind’s SSE protocol (meta, status, sources, action, text, done, error) is a small home-made version of the AG-UI idea.
  • Prompt chaining: split a task into several LLM calls where each output feeds the next (outline → sections → polish). Easier to validate and debug than one giant prompt.
  • Context compression: shrink what you send: summarise old history, trim tool results, extract only relevant sentences from chunks, deduplicate; keep a token budget.
  • Semantic caching: embed the incoming prompt; if a previous prompt is similar above a strict threshold (and same user scope/document version), return the cached answer. Risky for personalised or time-sensitive answers; exact caches and provider prompt caching are safer first steps.
  • Guardrails: checks before and after the model: input (length, PII, abuse, injection heuristics, topic scope) and output (schema, toxicity, grounding, no secrets, no HTML).
  • Model routing: choose a model per request by task or difficulty (small model for classification/rewrites, large for hard generation). DocMind’s intent router is routing of a different kind (paths, not models).
  • Fallback routing: an ordered list of models/providers tried on failure (with circuit breakers).
  • Evaluation frameworks: datasets + metrics + runners (e.g. RAGAS-style metrics, promptfoo, framework evals) to compare versions before shipping.
  • Observability: logs (events), metrics (numbers over time), traces (one request’s path as nested spans), plus AI-specific data: prompts, model, tokens, cost, tool calls, latency per step. OpenTelemetry with GenAI attributes, or LLM-tracing tools (Langfuse, LangSmith, Mastra’s tracing).

15.1AI orchestration

What is LangChain?A popular open-source library for building LLM applications from components: models, prompts, document loaders, text splitters, retrievers, tools and agents, with many integrations.Awareness. What is LangGraph?A library from the LangChain team for orchestrating agents and workflows as graphs: nodes do work, edges (including conditional and cyclic ones) decide what runs next, a shared state flows through, and checkpointers persist it for resume and human-in-the-loop interrupts.Awareness. How does LangChain differ from LangGraph?LangChain gives the building blocks and simple linear chains; LangGraph gives control flow and state for complex, cyclic, long-running agent processes with persistence. They’re often used together.Distinction. How does Mastra compare with these frameworks?Mastra is TypeScript-first and bundles agents, tools, workflows with suspend/resume and Postgres storage, memory, RAG helpers, evals and tracing in one framework. LangGraph is closer to Mastra’s workflows; LangChain to its building blocks. For a Node backend, Mastra fits naturally.Comparison. What is an orchestration framework?Software that coordinates multi-step LLM work: calling models and tools in order or in loops, passing state, retrying, pausing and resuming, and tracing what happened.Definition. When would you implement orchestration yourself?When the flow is small and stable, when you need precise control over a provider’s protocol, when the framework would add more concepts than code it saves, or when learning. Move to a framework once you need durable state, recovery and approvals.DocMind’s loop is ~1 file and taught me the protocol (thoughtSignature, tools omitted on the last step).Judgement. What is a multi-agent system?Several agents with different roles, tools or prompts cooperating on a task, coordinated by a supervisor agent, a workflow, or peer-to-peer messages.Awareness. What are the challenges of multi-agent communication?Lost or distorted context between agents, error propagation, loops between agents, cost and latency multiplying, unclear responsibility, harder debugging and evaluation, and security boundaries between agents’ permissions.Realism.

15.2MCP, A2A and AG-UI

What is MCP?The Model Context Protocol: an open standard for connecting AI applications to tools and data sources through MCP servers, so any MCP client can use any server.Awareness. What problem does MCP solve?The N×M integration problem: without it, every AI app writes its own connector for every system. With it, a system exposes one MCP server and every compatible app can use it.Purpose. What are MCP clients and servers?A server exposes capabilities (tools, resources, prompts) over JSON-RPC via stdio or HTTP. A client lives in a host application, connects to servers, discovers their capabilities and invokes them on behalf of the model.Architecture. What are MCP resources, tools and prompts?Tools: functions the model can call (with input schemas). Resources: data the app can read, addressed by URI (files, records). Prompts: reusable prompt templates the user or app can select.Vocabulary. What is A2A?The Agent2Agent protocol: an open standard for agents to discover each other (agent cards), send tasks, exchange messages and receive results and status updates, across frameworks and vendors.Awareness. What problem does A2A solve?Interoperability between independently built agents: delegating work to another team’s or vendor’s agent without knowing its internals, including long-running tasks.Purpose. How is A2A different from MCP?MCP connects an agent to tools and data (the agent stays in charge). A2A connects agents to other agents as peers (the remote agent decides how to do the task).Distinction. What is AG-UI?The Agent–User Interaction protocol: a standard event stream between an agent backend and a frontend (text deltas, tool calls, state updates, run lifecycle).Awareness. How does AG-UI connect an agent backend to a user interface?The frontend starts a run; the backend streams typed events (run started, text message content, tool call start/args/end, state snapshot/delta, run finished or error) over SSE or similar; the UI renders them and can send user input back.Mechanism. How do MCP, A2A and AG-UI fit into an AI application architecture?User ↔ AG-UI ↔ your agent; your agent ↔ MCP ↔ tools and data; your agent ↔ A2A ↔ other agents. Three layers, three protocols.Big picture.

15.3AI performance and reliability

What is prompt chaining?Breaking a task into several LLM calls in sequence, each with a focused prompt, where one call’s output feeds the next.Definition. What is context compression?Reducing the tokens sent while keeping what matters: summarising history, trimming tool results, extracting relevant sentences from retrieved chunks, deduplicating.Definition. What is semantic caching?Reusing a stored answer when a new request is semantically similar (embedding similarity above a threshold) to a previous one, scoped by user/tenant and data version.False hits: “refund for monthly plan” vs “refund for annual plan” may be very similar but need different answers. Use high thresholds, scope keys, TTLs, and only for non-personal FAQs.Trade-offs. What is an LLM guardrail?A check around model input or output that blocks, rewrites or flags content: schema validation, PII filters, topic restrictions, injection detection, grounding checks.Definition. What is model routing?Choosing which model handles a request based on task type, difficulty, cost or latency targets.Definition. What is fallback routing?Sending a request to a backup model or provider when the primary fails or times out.Definition. What is an LLM evaluation framework?Tooling to run a fixed dataset through a model or pipeline and score outputs with metrics (exact match, judge scores, faithfulness, latency, cost), so versions can be compared and regressions caught.Definition. What is observability in AI applications?Being able to see what happened inside each request: logs, metrics and traces plus prompts, model versions, tokens, cost, tool calls and per-step latency, so you can debug quality and cost, not only errors.Definition. What is the difference between logging and tracing?Logs are individual events (“tool failed”). Traces connect all the work for one request across components into a tree of timed spans with a shared id, showing order and where time went.Distinction. How would you monitor an agent’s execution?A trace per run with a span per model call (model, tokens, latency, finish reason) and per tool call (name, args summary, duration, outcome); counters for steps per run, loop-limit hits, tool error rate; sampled transcripts for review.Practice. How would you track token consumption across multiple agents?Record usage on every model call tagged with run id, agent name, user and feature; roll up per run and per user; propagate a run/trace id through agents so totals add up; budget per run.Practice. How would you measure end-to-end latency?From request received to last byte sent (and time to first token for streams), as p50/p95/p99, broken down by stage spans (auth, retrieval, each model call, tools, DB writes); also measured from the client for real user experience.Practice.
