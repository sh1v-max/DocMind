PART 1 · THE IDEA IN 60 SECONDS

An LLM does one thing: guess the next token. Then it does it again.

A large language model is a huge function. You give it a sequence of tokens (pieces of words), and it returns a probability for every token in its vocabulary being the next one. The app picks one, appends it, and calls the function again with the longer sequence. A whole answer is that loop running a few hundred times.

Everything else follows from this. It has no database of facts to look up, only patterns in its weights, so it can sound sure and be wrong. It keeps nothing between calls, so "memory" means resending the conversation. And it only sees what fits in its context window, so what you put in the prompt matters more than anything.

Analogy: autocomplete that read the internet. Your phone's keyboard suggests the next word from the last few words. An LLM does the same with thousands of tokens of context and billions of learned weights, well enough that the continuation reads like reasoning.

What it is

A next-token predictor (a transformer neural network) with weights frozen after training.

What it isn't

A database, a search engine, or something that learns from your chats. Nothing you send changes it.

What you control

The input (prompt, history, context, tools) and the sampling settings (temperature, top-p, max tokens).

PART 3 · TOKENS

Models read tokens, and you pay per token

Text is split into tokens by a tokenizer (usually BPE, byte-pair encoding): common words are one token, rare words split into pieces, and the leading space is usually part of the token. Rules of thumb for English: 1 token ≈ 4 characters ≈ 0.75 words, so 1,000 words ≈ 1,300 tokens. Code, numbers and non-English text usually take more tokens for the same meaning.

Why it matters for a backend
  • Price and rate limits (TPM = tokens per minute) are in tokens.
  • The context window is in tokens, not characters or messages.
  • Rare names split into pieces, which is one reason models misspell them.
  • Your two tool declarations cost ~136 input tokens on every agent call (measured in AG.0).
PART 4 · TEMPERATURE AND SAMPLING

How the next token gets picked

The model outputs a raw score per token (logits). Softmax turns them into probabilities. Before that, the scores are divided by the temperature: below 1 sharpens the distribution (the top token wins more), above 1 flattens it (unlikely tokens get a real chance). Top-p then keeps only the smallest set of tokens whose probabilities add up to p, and samples from those. Top-k does the same with a fixed count.

PART 5 · CONTEXT WINDOW AND MEMORY

Everything the model knows about this request has to fit in one window

The context window is the maximum number of tokens one call can hold: system instruction, history, retrieved chunks, the question, and the answer it writes. Go over it and the API refuses, or your app has to drop something first. Even well inside the limit, every token costs money and time, on every single call.

PART 6 · TRAINING, INFERENCE AND ATTENTION

Where the model's knowledge comes from, and what you can't change

1 · PRE-TRAINING · months, thousands of GPUs

Learn to predict text

  • Next-token prediction over a huge amount of text and code.
  • Facts, grammar and patterns end up in the weights.
  • Knowledge stops at the cutoff date.
2 · POST-TRAINING · weeks

Learn to be an assistant

  • Instruction tuning on example conversations.
  • Preference training (e.g. RLHF): humans or models rank answers.
  • Learns roles, refusals, tool calling, JSON mode.
3 · INFERENCE · your API call, every request

Use it, weights frozen

  • Only forward passes; nothing is learned.
  • You change the input (prompt, context, tools) and the sampling.
  • This is where all of DocMind lives.

Fine-tuning is a small extra round of training on your own examples. It changes behaviour and format well, and adds facts badly. Lesson 6 covers RAG vs fine-tuning.

Attention, in one picture

A transformer builds each token's meaning by looking at the other tokens in the context, with learned weights for how much each one matters. That's attention. Click a word to see where it might "look". Real models have dozens of layers, each with many attention heads looking for different things.

Click "it".

Example weights. Two consequences you'll be asked about: standard attention compares every token with every other, so cost grows with the square of the length; and during generation the model caches what it computed for earlier tokens (the KV cache), so each new token only adds one row.

PART 7 · WHAT BIT YOU

LLM behaviour you ran into while building DocMind

22 / 36 / 32 / 10%

Models aren't random

Across 50 quiz questions, the correct answer sat in position A/B/C/D that often. A model has habits; "valid" isn't "fair". You shuffle the options in code.

T = 0

A classifier must be boring

The router's LLM classifier runs at temperature 0 with JSON mode and a Zod check. Same message, same label, and a malformed reply is caught, not trusted.

1–3 s vs 25–53 s

Same call, different day

The classifier took 1–3 s one day and 25–53 s another, with 503 "high demand" errors. Latency is not a property of your code. Don't redesign from one slow run.

-latest

The model can change under you

gemini-flash-lite-latest turned out to be gemini-3.5-flash-lite (from modelVersion in the reply). An alias can move to a new model with different behaviour, with no deploy on your side.

"Paris!"

Training knowledge leaks

Asked "capital of France?", the chat answered from what the model learned in training. Stopping that took explicit rules, because the model knows plenty that isn't in your PDF.

132 chars

Thinking models leave traces

Every model turn came with a thoughtSignature. Drop it when sending a turn back and Gemini answers 400. Reasoning models carry hidden state you must return untouched.

15 RPM · 500 RPD

Limits are part of the design

Flash-Lite's free tier on your account. Every extra call per question (the classifier, an agent step) spends this budget, which is why the router tries vectors first.

no timeout

An open gap (ISSUES #8)

No Gemini fetch has a timeout or retry yet, so a hung call hangs the request. A good "what would you improve?" answer.

PART 8 · INTERVIEW DRILL

32 questions you could get. Answer out loud first, then open.

Say it in 60 seconds: "How does an LLM actually work?"

"It's a transformer trained to predict the next token. Text is split into tokens; the model reads all of them, using attention so each token's meaning depends on the others, and outputs a probability for every possible next token. The app samples one, controlled by temperature and top-p, appends it and repeats until a stop token or the length limit. The knowledge is frozen in the weights at training time, the model keeps no state between calls, and it can only see what fits in its context window. So in a backend, the real work is deciding what goes into that window, which is what RAG and conversation memory do in my project."

Each answer opens with Say this first: the 10-second version to lead with. Then the fuller explanation, an example, how it applies in DocMind, the likely follow-up, and the wrong answer to avoid. Say the short answer, then go deeper only if they ask.
